# QloApps on Railway

Deployment image for [QloApps](https://github.com/Qloapps/QloApps) — an open-source
hotel Property Management System, booking engine and hotel website, built on the
PrestaShop 1.6 core.

The published `webkul/qloapps_docker` image is a single-box development build: it
bundles its own MySQL server and an SSH daemon under supervisord, and it expects a
human to click through the web installer. This repository builds a deployment image
instead — one Apache/mod_php container that installs itself headlessly against an
external MySQL server on first boot.

## What the image does

- `php:8.3-apache` with the extensions QloApps' own requirement checker asks for
  (`gd`, `intl`, `zip`, `soap`, `bcmath`, `pdo_mysql`, `mysqli`, `exif`, `opcache`).
- Provisions a **scoped database role** at boot from the admin connection string, so
  the application never runs as the managed database's superuser.
- Runs `install/index_cli.php` on the first boot only, creating the first admin from
  `QLO_ADMIN_EMAIL` / `QLO_ADMIN_PASSWORD` — there is no window in which the shop is
  reachable without an owner, and no setup wizard to click through.
- Re-applies the shop URL, the HTTPS flags and (once) the SMTP settings on every
  boot, so a regenerated Railway domain or a new custom domain is picked up.
- Serves `/healthz` from an Apache `Alias` outside the application tree. It opens the
  shop's own database connection and reads a row, so it is a real dependency probe
  and no application redirect can fail it.
- Sizes Apache's prefork pool from the container's cgroup memory limit rather than
  from the host.
- Deletes `install/` once the schema exists.

## Persistence

One volume, mounted at **`/data`**. The image moves every directory QloApps writes to
out of the application tree and symlinks it back, so the volume never hides the files
the image ships:

| Path on the volume | Behaviour |
|---|---|
| `img`, `upload`, `download` | operator content — only ever filled in, never overwritten |
| `modules`, `themes`, `translations`, `mails` | upstream code — refreshed whenever the image version changes |
| `config/settings.inc.php` | generated by the installer; holds `_COOKIE_KEY_`, which QloApps hashes employee passwords with |
| `log`, `.htaccess` | application-written |

## Environment

Everything has a working default except the two passwords.

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `8080` | port Apache listens on |
| `MYSQL_URL` | — | admin connection string; `MYSQL_ADMIN_HOST` / `_PORT` / `_USER` / `_PASSWORD` are the discrete alternative |
| `QLO_DB_NAME` / `QLO_DB_USER` | `qloapps` | database and scoped role created at boot |
| `QLO_DB_PASSWORD` | — | **required**; password for that role |
| `QLO_DB_PREFIX` | `qlo_` | table prefix |
| `QLO_ADMIN_EMAIL` | `admin@example.com` | first admin |
| `QLO_ADMIN_PASSWORD` | — | **required** on the first boot; at least 8 characters |
| `QLO_ADMIN_FIRSTNAME` / `QLO_ADMIN_LASTNAME` | `Hotel` / `Manager` | first admin's name |
| `QLO_ADMIN_DIR` | `backoffice` | back-office directory. QloApps refuses to serve a back office named `admin`, so this can never be `admin`; set something unguessable |
| `QLO_SHOP_NAME` | `QloApps Hotel` | shop name |
| `QLO_SHOP_COUNTRY` | `us` | ISO country used to seed taxes, currency and address format |
| `QLO_SHOP_LANGUAGE` | `en` | installation language |
| `QLO_SHOP_TIMEZONE` | `UTC` | PHP and shop timezone |
| `QLO_SHOP_EMAIL` | `QLO_ADMIN_EMAIL` | From address on outgoing mail |
| `QLO_INSTALL_FIXTURES` | `1` | install the demo hotel; set `0` for an empty shop |
| `QLO_PUBLIC_DOMAIN` | `RAILWAY_PUBLIC_DOMAIN` | host the shop answers on; set it for a custom domain |
| `QLO_SMTP_HOST` | unset | SMTP server, seeded into the shop's mail settings once |
| `QLO_SMTP_PORT` / `QLO_SMTP_ENCRYPTION` | `1025` / `off` | SMTP transport |
| `QLO_SMTP_USER` / `QLO_SMTP_PASSWORD` | empty | SMTP credentials |
| `PHP_MEMORY_LIMIT` | `512M` | PHP memory limit |
| `PHP_UPLOAD_MAX_FILESIZE` / `PHP_POST_MAX_SIZE` | `64M` | media upload ceiling |
| `PHP_MAX_EXECUTION_TIME` | `300` | PHP execution ceiling |
| `APACHE_MAX_WORKERS` | derived from the cgroup | prefork `MaxRequestWorkers` |
